# goal

Prove the distribution mechanism once: from mitosys — the strict consumer tree —
depend on `conserved` through the decided git-dependency-pinned-by-rev
mechanism, build it, observe what mitosys's dependency gate says about it, and
record the result with the rev in `.mi/prd/p1-scope/proof.md`.

This is requirement 3 of the ticket. **It is not adoption.** One crate, one
build, one record. mitosys keeps its own `util/effect`, nothing in mitosys's
committed tree changes, and reconciling the two copies is `p5-adoption`.

## What must have landed first

- **p0** — this repository is a git repository with commits
  (`p0-foundation` requirement 1). A git dependency pinned by rev has no
  subject without that.
- **p0** — `.mi/docs/memos/distribution.md` reads `status: decided`: Option A,
  git dependency pinned by commit rev, with mitosys's offline-container story
  explicitly scoped as mitosys-side follow-up work and explicitly **not** a
  blocker for p1. This spec does not reopen either question.
- **spec01, committed.** The rev pinned here is the commit that carries
  `conserved/src/scope.rs`. A dirty working tree cannot be pinned; the port must
  be committed before this spec runs, and `git rev-parse HEAD` after that commit
  is the rev.

## The URL, and the one deviation from the decided mechanism

p0 runs `git init` and adds no remote, so there is no fetchable https URL for
this repository yet. Cargo's git source takes a `file://` URL and treats it the
same way — same fetch, same rev pin, same lock entry — so the proof uses:

```toml
conserved = { git = "file:///Users/feb/dev/infra/shared", rev = "<sha>" }
```

This was checked during analysis against cargo 1.94.0: the dependency resolves,
locks and compiles, and the second build succeeds under `--offline` because the
first populated the cache. **The first build cannot run under `--offline`** —
that is exactly the container cost the distribution memo assigns to mitosys as
follow-up work, and it is out of scope here. When this repository gains a
remote, `p5-adoption` swaps the URL; the `rev =` half — which is the part being
proven — does not change. Record this deviation in `proof.md`.

Touched **only inside a throwaway git worktree** of mitosys, never in
`/Users/feb/dev/infra/mitosys` itself:

- `Cargo.toml` — one line in `[workspace.dependencies]`. mitosys pins shared
  dependencies once at the workspace root and gates it (`AGENTS.md`
  §divergences); a git dep declared straight in a member manifest would prove
  the mechanism against a convention mitosys does not use.
- `src/mitosys/util/effect/Cargo.toml` — `conserved = { workspace = true }`.
  This crate is the natural consumer: it is the one whose module `conserved`
  now also holds, so it is the pair `p5` will actually reconcile.
- `src/mitosys/util/effect/tests/conserved_pin.rs` — a smoke test, ~6 lines,
  that constructs a `conserved::scope::Scope`, registers one effect, closes it
  and asserts the inverse ran. A declared-but-unused dependency proves that
  cargo resolved a manifest entry; this proves the symbols cross the crate
  boundary, which is what "the mechanism works" has to mean. mitosys's own gate
  doc calls declared-but-unused dependencies a defect shape by name.
- `src/mitosys/gates/tests/dependency_tree.rs` — two lines, added only to
  observe the gate go green again: `("conserved", &["mitosys-util-effect"])` in
  `OWNERS`, and `"conserved"` in `CLOSURE`. Both lists are sorted; keep them
  sorted.
- `Cargo.lock` — regenerated by the build. mitosys's gate runs
  `cargo metadata --locked`, so a manifest edited without the lock updated fails
  loudly there rather than silently.

**mitosys's working tree is not the place any of this happens.** It is a git
repository on `main` with unrelated uncommitted work in it right now, so a
`git checkout -- .` cleanup would destroy someone else's changes. Use:

```sh
git -C /Users/feb/dev/infra/mitosys worktree add --detach <scratch>/mitosys-p1-proof HEAD
# … the five edits above, the build, the gate run, transcribe into proof.md …
git -C /Users/feb/dev/infra/mitosys worktree remove --force <scratch>/mitosys-p1-proof
```

`mitosys-util-effect` has zero dependencies and `mitosys-gates` has only a
`serde_json` dev-dependency, so both targets build cheaply in a cold worktree.

Not touched: anything under `conserved/` (spec01 owns it), `learnings/`,
`.mi/docs/memos/`, any other consumer tree (`../model`, `../realm`) — the
ticket says one consumer tree, and full adoption is p5.

## The gate observation, and why it is the real result

mitosys's `src/mitosys/gates/tests/dependency_tree.rs` records every third-party
crate the harness declares (`OWNERS`) and its whole transitive closure
(`CLOSURE`); a git dependency is not a workspace member, so `conserved` counts
as third-party and both lists move. The result worth recording is the *size* of
the move:

- **before** the two-line record update, the gate fails, naming `conserved` as
  new — proof the strict tree actually sees the dependency;
- **after**, the gate passes, and the diff to the gate file is exactly those two
  lines. Any third line means `conserved` dragged something in, and requirement
  2 of this ticket is false from the consumer side, not just from
  `cargo tree`'s.

That is the consumer-side form of "zero dependencies", and it is what makes this
proof worth more than one `cargo build`.
